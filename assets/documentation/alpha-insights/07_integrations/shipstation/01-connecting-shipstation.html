Connecting ShipStation

Alpha Insights can sync shipping costs from ShipStation with your WooCommerce orders. Once configured and enabled, a daily sync runs automatically for the last 7 days of purchased labels, and you can run a one-time bulk sync to backfill historical data. Synced costs are saved to orders, and optionally as record-keeping expenses, for accurate profit reporting.

What the integration does

  • Syncs purchased label cost from ShipStation to WooCommerce orders by matching external_order_id, external_shipment_id, or shipment_number to your WooCommerce order number
  • Runs a daily sync that fetches completed labels from the past 7 days (paginated, 500 per page) and processes each label
  • Optionally runs a bulk sync (all completed labels, paginated) when you click Run bulk sync; if the API rate limit is hit, the current page is rescheduled and retried later
  • Saves shipment_cost + insurance_cost (the actual carrier/label spend) to order meta (_wpd_ai_total_shipping_cost, _wpd_ai_shipstation_shipping_cost, and optionally _wpd_ai_shipstation_shipment_id)
  • Optionally creates a record-keeping expense for each synced order (reference: ShipStation - {order_id}), categorized as Shipping. These expenses are excluded from P&L because the cost already lives on the order. Expense date comes from the label created_at (UTC converted to your site timezone) or the order date
  • Recalculates order profit after each successful sync

Requirements

  • Alpha Insights Pro with ShipStation integration available
  • WooCommerce with orders (order numbers can be default or custom, e.g. Sequential Order Numbers)
  • A ShipStation API v2 key (API Key authentication). This is not the older API Key + API Secret / Basic Auth pair
  • Action Scheduler (included with WooCommerce) for daily and bulk sync

Settings

Go to Alpha Insights → Settings and open the Integrations tab. Find the ShipStation section.

Enable Integration

Turn on ShipStation sync. The integration only runs when this is checked and an API key is set.

API Key

Your ShipStation API v2 key. Required when the integration is enabled. Alpha Insights sends it as the api-key header. Create this key in ShipStation under API settings (API Key authentication only).

Enable Logging

When enabled, API requests and sync activity are written to the ShipStation log file. Errors are always logged to the ShipStation error log regardless of this setting.

Save costs as record-keeping expenses

When enabled, each sync also creates a record-keeping expense in the expenses list. Record-keeping expenses are documentation only and are excluded from P&L. Profit still uses order meta (_wpd_ai_shipstation_shipping_cost / _wpd_ai_total_shipping_cost).

ShipStation Sync Data section

  • Next Scheduled Sync – When the next daily sync will run. The daily schedule fetches completed labels for the past 7 days.
  • Sync stats – Number of orders with synced shipping cost and number of expenses created from ShipStation syncs.
  • Bulk Sync – Button to run a full sync of all completed labels. Only shown when the integration is enabled. Runs in the background; if rate limited, pages are rescheduled automatically.
  • Delete sync data – Removes all ShipStation data: shipping cost meta from orders and all expenses with reference starting with ShipStation - . Use with care.

How to set up

  1. Create an API v2 key in ShipStation (Account → API Settings, API Key authentication).
  2. In WordPress, go to Alpha Insights → Settings → Integrations.
  3. Check Enable ShipStation integration.
  4. Enter the API key.
  5. Optionally enable Enable ShipStation logging for debugging.
  6. Click Save changes. The daily sync is scheduled on the next run of Alpha Insights’ event scheduler. Use Run bulk sync if you want to backfill past labels.

How the sync works

Which cost is saved

Alpha Insights uses the ShipStation Labels API, not the shipment retail rate or the amount the customer paid for shipping. For each completed, non-voided, non-return label it adds:

  • shipment_cost.amount — carrier shipping, confirmation, and other label charges
  • insurance_cost.amount — insurance charged on that label

Multiple outbound labels for the same order in the same sync run are summed.

Daily sync

  • Runs once per day.
  • Fetches completed labels with created_at in the last 7 days, sorted by create date descending, 500 per page.
  • For each label, matches external_order_id, external_shipment_id, or shipment_number (plus those fields on the linked shipment when needed) to a WooCommerce order.
  • Saves the label cost to the order and creates or updates the ShipStation record-keeping expense.

Bulk sync

  • Triggered by the Run bulk sync button. Schedules page 1; each page run schedules the next page until all pages are processed.
  • Fetches all completed labels (no date filter), 500 per page. If the API returns 429 (rate limit), the same page is rescheduled in 90 seconds.
  • Same matching and processing as daily sync: order number → order, then save cost and expense.

Order matching

ShipStation uses order number, not internal WooCommerce order ID. From each label (and its linked shipment when available) Alpha Insights collects non-empty values from external_order_id, external_shipment_id, and shipment_number. Different store integrations populate different fields; the first value that matches a WooCommerce order is used. Then it finds the WooCommerce order by:

  • If the order number is numeric, trying wc_get_order( order_number ) and confirming the order’s get_order_number() matches.
  • Otherwise searching for an order with _order_number meta equal to the ShipStation order number (supports custom order number plugins).

Order meta and expenses

When a label is processed successfully:

  • Order meta: _wpd_ai_total_shipping_cost, _wpd_ai_shipstation_shipping_cost, and _wpd_ai_shipstation_shipment_id (if present on the label).
  • Expense: One record-keeping expense per order with reference ShipStation - {order_id}, category Shipping, and date from the label created_at (UTC → site timezone) or the order’s date paid/created. Existing ShipStation expenses are updated to record keeping and refreshed with the latest label cost.

Connection debugger

At the bottom of the ShipStation settings (above the logs) there is a Connection debugger. With no order number, it fetches labels from the last N days (1–30), newest first, and shows the most recent 50. Enter an order number to look up that order at any age via ShipStation external_order_id, external_shipment_id, or shipment_number. Nothing is written to orders or expenses.

Use it to confirm:

  • The API key is accepted (a connection error is shown if it is not)
  • Labels exist in the date range you expect
  • Order numbers on the labels match WooCommerce orders
  • Label cost is shipment_cost + insurance_cost
  • Whether each label would be picked up by daily sync (completed, not voided, not a return, cost greater than zero, matching order)

Expand Raw API labels (first page) to inspect the JSON ShipStation returned. Daily sync still only processes completed labels from the last 7 days; this tool can show other statuses so you can see why a label was skipped.

Troubleshooting

Integration not running

  • Ensure Enable Integration is checked and the API key is saved and non-empty.
  • Check WooCommerce → Status → Scheduled Actions for wpd_ai_shipstation_sync_costs_with_orders (daily) and wpd_ai_shipstation_bulk_sync_page (bulk).
  • Enable logging and check the ShipStation log and ShipStation error log at the bottom of the Integrations settings.
  • Use the Connection debugger to fetch recent labels and confirm the API key and payload without running a sync.

Orders not getting a shipping cost

  • Confirm the order number in WooCommerce matches external_order_id, external_shipment_id, or shipment_number in ShipStation.
  • If you use a custom order number plugin, ensure the order number is stored in a way the integration can find (e.g. _order_number meta or that the numeric ID matches the displayed number).
  • Ensure the label is completed (not voided or a return) and that shipment_cost + insurance_cost is greater than zero.

Cost does not match the customer-paid shipping amount

That is expected. Alpha Insights stores the label/carrier cost, not the shipping amount charged to the customer. Customer-paid shipping stays on the WooCommerce order as revenue; the ShipStation label cost is the expense used for profit.

Rate limiting (429)

During bulk sync, if ShipStation returns 429 or the request times out, the current page is automatically rescheduled to run again in 90 seconds. No action needed; let the queue finish. List requests use a page size of 100 (not the API maximum of 500) because larger pages often hang until the HTTP timeout.

Removing ShipStation data

Use Delete sync data to remove all ShipStation shipping cost meta from orders and all expenses with reference ShipStation - . This does not remove the integration settings; you can run sync again after re-saving or re-enabling.
